Custom Icon Pack

Overview

What you are building

A clean Avalonia 12 app built from scratch that extends DefaultTheme's icon gallery in all four ways: inheriting built-in glyphs, overriding an existing glyph (ChevronDown), generating typed tokens automatically from Icons/Svg/*.svg files, and adding hand-written paths & aliases in C#.

Phase 1 · Project & Packages

Create the project from scratch

Start from a fresh Avalonia MVVM app, remove Fluent and the template Inter font package, and install AngelSix.Themes.Default and AngelSix.ThemeEngine (which contains the SVG-to-token source generator).

  1. First we create a clean Avalonia project and solution so we have a blank canvas for our custom icon pack.

    dotnet new avalonia.mvvm -n MyIconsApp
dotnet new sln -n MyIconsApp --format sln
dotnet sln MyIconsApp.sln add MyIconsApp/MyIconsApp.csproj

  2. Since we're using DefaultTheme and AngelSix.Mvvm instead of Fluent and CommunityToolkit, we remove Avalonia.Themes.Fluent2 (or Avalonia.Themes.Fluent on older templates), Avalonia.Fonts.Inter, and CommunityToolkit.Mvvm right away.

    dotnet remove MyIconsApp package Avalonia.Themes.Fluent2
dotnet remove MyIconsApp package Avalonia.Themes.Fluent
dotnet remove MyIconsApp package Avalonia.Fonts.Inter
dotnet remove MyIconsApp package CommunityToolkit.Mvvm

    Newer Avalonia 12 templates reference Avalonia.Themes.Fluent2 while older ones reference Avalonia.Themes.Fluent — remove whichever is in your .csproj.

  3. Now we add AngelSix.Themes.Default for the base icons and controls, plus AngelSix.ThemeEngine so its source generator can turn our SVG files into XAML tokens.

    dotnet add MyIconsApp package AngelSix.Themes.Default
dotnet add MyIconsApp package AngelSix.ThemeEngine
    Why add AngelSix.ThemeEngine directly?The Roslyn source generator that scans Icons/Svg/*.svg and emits typed {icons:…} markup extensions lives in AngelSix.ThemeEngine.

  4. Because this icon showcase needs no ViewModels, we delete the template's unused ViewModels and ViewLocator and drop .WithInterFont() from Program.cs.

    This app needs no ViewModels at all (the Light/Dark switch binds straight to IconsTheme.Current.IsDark). Delete the template's ViewModels/ folder and ViewLocator.cs, and remove .WithInterFont() from Program.cs.

    Added / changedRemoved
    Program.cs
    using Avalonia;
using System;

namespace MyIconsApp;

sealed class Program
{
    [STAThread]
    public static void Main(string[] args) => BuildAvaloniaApp()
        .StartWithClassicDesktopLifetime(args);

    // Avalonia configuration, don't remove; also used by visual designer.
    // No font call: the theme registers its own fonts (AngelSix.ThemeEngine.Fonts).
    public static AppBuilder BuildAvaloniaApp()
        => AppBuilder.Configure<App>()
            .UsePlatformDetect()
#if DEBUG
            .WithDeveloperTools()
#endif
            .WithInterFont()
            .LogToTrace();
}

Phase 2 · SVG Icon Files

Drop raw .svg files into Icons/Svg/

Every .svg file placed inside Icons/Svg/ becomes a generated property on your [IconGallery] class — one file, one compile-time XAML token, zero runtime SVG parsing.

  1. Before writing our icon gallery class, we drop our first raw SVG (Label.svg) into Icons/Svg/ so the source generator has real files to discover.

    Icons/Svg/Label.svgNew file

  2. Next we add Coffee.svg into the same folder — we'll also alias this icon in C# later to show how aliases work.

    Icons/Svg/Rocket.svgNew file

Phase 3 · Icon Gallery & Theme

Declare AppIcons and attach it to IconsTheme

Combine the auto-generated SVG icons with an override (ChevronDown), a hand-written path (Heart), and an alias (CoffeeCup), then activate your theme in App.axaml.

  1. With our SVG files in place, we declare AppIcons (adding an override, a literal path, and an alias) and link it into IconsTheme : DefaultTheme.

    Notice [IconGallery(Folder = "Icons/Svg")] points the generator at your SVG folder while deriving from ThemeIconGallery preserves every built-in icon from DefaultTheme.

    Theme/IconsTheme.csNew file
    using AngelSix.ThemeEngine;
using AngelSix.Themes.Default;

namespace MyIconsApp.Theme;

/// <summary>The app's theme: the default theme, plus a custom icon gallery.</summary>
[Theme(FallbackHue = "Neutral")]
public sealed partial class IconsTheme : DefaultTheme
{
    #region Properties

    public override AppIcons Icons { get; } = new();

    #endregion Properties
}

/// <summary>
/// The app's icons. Deriving from <see cref="ThemeIconGallery"/> keeps every default icon
/// alive — <c>{icons:Close}</c> and friends still work — while the SVG folder and the
/// hand-written properties below add to it and redraw from it.
/// </summary>
[IconGallery(SvgFolder = "Icons/Svg")]
public partial class AppIcons : ThemeIconGallery
{
    #region Properties

    /// <summary>Hand-written: one path string is the whole drawing.</summary>
    public virtual string Heart => "M12 21.35l-1.45-1.32C5.4 15.36 2 12.28 2 8.5 2 5.42 4.42 3 7.5 3c1.74 0 3.41.81 4.5 2.09C13.09 3.81 14.76 3 16.5 3 19.58 3 22 5.42 22 8.5c0 3.78-3.4 6.86-8.55 11.54L12 21.35z";

    /// <summary>An alias: a hand-written name pointing at a generated one.</summary>
    public virtual string CoffeeCup => Coffee;

    /// <summary>Redrawing a default icon replaces it everywhere — this theme's templates included.</summary>
    public override string ChevronDown => "M5 8l7 7 7-7 2 2-9 9-9-9z";

    #endregion Properties
}

  2. Since we're using our own IconsTheme instead of Fluent, we remove Fluent2Theme (or FluentTheme on older templates) and the unused ViewLocator from App.axaml and plug in IconsTheme.

    Added / changedRemoved
    App.axaml
    <Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="MyIconsApp.App"
             xmlns:local="using:MyIconsApp"
             xmlns:local="using:MyIconsApp.Theme"
             RequestedThemeVariant="Default">
    <Application.DataTemplates>
        <local:ViewLocator/>
    </Application.DataTemplates>
    <Application.Styles>
        <Fluent2Theme /> <!-- or <FluentTheme /> on older templates -->
        <local:IconsTheme />
    </Application.Styles>
</Application>

  3. Because we deleted the template's MainViewModel earlier, we simplify App.axaml.cs so it opens MainWindow directly.

    Remove the deleted MainViewModel reference so App.axaml.cs creates MainWindow directly.

    Added / changedRemoved
    App.axaml.cs
    using Avalonia;
using Avalonia.Controls.ApplicationLifetimes;
using Avalonia.Markup.Xaml;
using MyIconsApp.ViewModels;
using MyIconsApp.Views;

namespace MyIconsApp;

public partial class App : Application
{
    public override void Initialize() => AvaloniaXamlLoader.Load(this);

    public override void OnFrameworkInitializationCompleted()
    {
        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
            desktop.MainWindow = new MainWindow { DataContext = new MainViewModel() };
            desktop.MainWindow = new MainWindow();

        base.OnFrameworkInitializationCompleted();
    }
}

Phase 5 · Build & Run

Verify your custom icon pack

  1. Let's build and launch the app to see the source-generated icons rendered live.

    dotnet run --project MyIconsApp/MyIconsApp.csproj

  2. Finally, check all four cards and flip Dark mode to confirm every built-in, overridden, SVG, and hand-written icon adapts cleanly.

    • Built-in + override: Close, WindowMaximize, and WindowRestore still render, while ChevronDown uses your custom redraw.
    • SVG files: Label, Coffee, and Rocket were generated directly from Icons/Svg/*.svg.
    • C# paths & aliases: Heart renders your literal path and CoffeeCup mirrors Coffee.
    • Live Dark mode: flip the top-right toggle and watch every card, icon, and button adapt cleanly.
