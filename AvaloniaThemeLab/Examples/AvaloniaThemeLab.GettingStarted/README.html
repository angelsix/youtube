Overview

What you are building

A clean Avalonia 12 desktop app wired with dependency injection, AngelSix.Mvvm and AngelSix.Themes.Default. Every control is styled by the default theme, with live light/dark switching, live UI scaling and semantic accent buttons.

1. Projectdotnet new, clean template & packages
2. ThemeSwap Fluent for <DefaultTheme />
3. DI & VM shellMinimal VM + App.axaml.cs
4. ViewModelGreeting & live theme commands
5. View & RunMainWindow.axaml, build & launch
Prerequisites.NET 10 SDK and the Avalonia project templates installed once on your machine: 
dotnet new install Avalonia.Templates

Phase 1 · Project & Packages

Create the project and swap the packages

Start from the official Avalonia MVVM template, put it inside its own solution, remove Fluent and the duplicate Inter font package, and add the default theme plus DI.

  1. We need a clean, runnable Avalonia desktop project and solution file as our starting point before we wire up the theme.

    dotnet new avalonia.mvvm -n AvaloniaThemeLab.GettingStarted
dotnet new sln -n AvaloniaThemeLab.GettingStarted --format sln
dotnet sln AvaloniaThemeLab.GettingStarted.sln add AvaloniaThemeLab.GettingStarted/AvaloniaThemeLab.GettingStarted.csproj

    This creates the standard Avalonia 12 MVVM structure in a solution of its own. Open AvaloniaThemeLab.GettingStarted.sln in Rider rather than opening the folder — Rider reads the theme engine's live templates from the solution's .DotSettings file.

  2. Since our app uses the AngelSix Theme Engine and AngelSix.Mvvm, we strip out FluentTheme (or Fluent2Theme on newer Avalonia templates), the template's Inter font, and CommunityToolkit.Mvvm so nothing clashes with our theme or MVVM base classes.

    dotnet remove AvaloniaThemeLab.GettingStarted package Avalonia.Themes.Fluent2
dotnet remove AvaloniaThemeLab.GettingStarted package Avalonia.Themes.Fluent
dotnet remove AvaloniaThemeLab.GettingStarted package Avalonia.Fonts.Inter
dotnet remove AvaloniaThemeLab.GettingStarted package CommunityToolkit.Mvvm

    Newer Avalonia 12 templates reference Avalonia.Themes.Fluent2 while older ones reference Avalonia.Themes.Fluent — remove whichever is in your .csproj. Removing CommunityToolkit.Mvvm ensures ViewModelBase and ObservableObject resolve to AngelSix.Mvvm rather than CommunityToolkit. AngelSix.Themes.Default styles every control itself and registers its own bundled Inter font (AngelSix.ThemeEngine.Fonts).

  3. Now we pull in the Default Theme (which also brings the Theme Engine and MVVM helpers) plus Microsoft's DI container so our ViewModels can receive the theme cleanly.

    dotnet add AvaloniaThemeLab.GettingStarted package AngelSix.Themes.Default
dotnet add AvaloniaThemeLab.GettingStarted package Microsoft.Extensions.DependencyInjection

    AngelSix.Themes.Default automatically brings in AngelSix.ThemeEngine and AngelSix.Mvvm — no separate MVVM package install is needed.

  4. Because we removed the template's Inter font and CommunityToolkit.Mvvm, we drop .WithInterFont(), delete the template's ViewModelBase and MainViewModel, and point ViewLocator at AngelSix.Mvvm.ViewModelBase.

    Delete the template's ViewModels/ViewModelBase.cs (which referenced CommunityToolkit) and unused ViewModels/MainViewModel.cs, remove .WithInterFont() from Program.cs, and update ViewLocator.cs to import AngelSix.Mvvm so data is ViewModelBase matches our AngelSix.Mvvm.ViewModelBase. Clicking Copy copies the clean final file with removed lines omitted.

    Added / changedRemoved
    Program.cs
    using Avalonia;
using System;

namespace AvaloniaThemeLab.GettingStarted;

sealed class Program
{
    [STAThread]
    public static void Main(string[] args) => BuildAvaloniaApp()
        .StartWithClassicDesktopLifetime(args);

    // Avalonia configuration, don't remove; also used by visual designer.
    // No font call: the theme registers its own fonts (AngelSix.ThemeEngine.Fonts).
    public static AppBuilder BuildAvaloniaApp()
        => AppBuilder.Configure<App>()
            .UsePlatformDetect()
#if DEBUG
            .WithDeveloperTools()
#endif
            .WithInterFont()
            .LogToTrace();
}
    ViewLocator.cs
    using System;
using System.Diagnostics.CodeAnalysis;
using AngelSix.Mvvm;
using Avalonia.Controls;
using Avalonia.Controls.Templates;
using AvaloniaThemeLab.GettingStarted.ViewModels;

namespace AvaloniaThemeLab.GettingStarted;

public class ViewLocator : IDataTemplate
{
    public Control? Build(object? param)
    {
        if (param is null) return null;
        var name = param.GetType().FullName!.Replace("ViewModel", "View", StringComparison.Ordinal);
        var type = Type.GetType(name);
        if (type != null) return (Control)Activator.CreateInstance(type)!;
        return new TextBlock { Text = "Not Found: " + name };
    }

    public bool Match(object? data) => data is ViewModelBase;
}

Phase 2 · Enable the Theme

Swap Fluent for <DefaultTheme />

One line in App.axaml activates the entire theme — every control theme, color ramp, size ladder and font loads automatically.

  1. With the packages in place, we swap out Avalonia's Fluent2Theme (or FluentTheme on older templates) for DefaultTheme in App.axaml so every control immediately picks up the AngelSix styling.

    App.axaml
    <Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="AvaloniaThemeLab.GettingStarted.App"
             xmlns:local="using:AvaloniaThemeLab.GettingStarted"
             RequestedThemeVariant="Default">

    <Application.DataTemplates>
        <local:ViewLocator/>
    </Application.DataTemplates>

    <Application.Styles>
        <Fluent2Theme /> <!-- or <FluentTheme /> on older templates -->
        <DefaultTheme />
    </Application.Styles>
</Application>
    No extra xmlns neededDefaultTheme registers itself into Avalonia's default XML namespace, so you drop it straight into <Application.Styles> in place of <Fluent2Theme /> / <FluentTheme />.

Phase 3 · ViewModel Shell & Dependency Injection

Prepare the ViewModel shell, then wire DI in App.axaml.cs

To keep the project compiling at every step, start with a bare MainWindowViewModel that accepts DefaultTheme in its constructor, then jump straight into App.axaml.cs to register both in DI.

  1. Before we wire up Dependency Injection in App.axaml.cs, we create a tiny MainWindowViewModel shell first so the project stays compiling at every step.

    Create ViewModels/MainWindowViewModel.cs inheriting from ViewModelBase (provided by AngelSix.Mvvm, so Avalonia's ViewLocator matches it automatically) and taking DefaultTheme through its primary constructor. We will flesh out its properties and commands right after DI is wired.

    ViewModels/MainWindowViewModel.csNew file
    using AngelSix.Mvvm;
using AngelSix.Themes.Default;

namespace AvaloniaThemeLab.GettingStarted.ViewModels;

public sealed partial class MainWindowViewModel(DefaultTheme theme) : ViewModelBase
{
    public DefaultTheme Theme { get; } = theme;
}

  2. Now we register DefaultTheme.Current and MainWindowViewModel in DI and implement IServiceHost so both the running app and the XAML designer get the real ViewModel.

    Implement IServiceHost on App, build the service provider after AvaloniaXamlLoader.Load(this) so DefaultTheme.Current exists, register the theme and MainWindowViewModel, and resolve the view model when creating MainWindow.

    App.axaml.cs
    using System;
using AngelSix.Mvvm;
using AngelSix.Themes.Default;
using Avalonia;
using Avalonia.Controls.ApplicationLifetimes;
using Avalonia.Markup.Xaml;
using AvaloniaThemeLab.GettingStarted.ViewModels;
using AvaloniaThemeLab.GettingStarted.Views;
using Microsoft.Extensions.DependencyInjection;

namespace AvaloniaThemeLab.GettingStarted;

public partial class App : Application
public partial class App : Application, IServiceHost
{
    public IServiceProvider Services { get; private set; } = null!;

    public override void Initialize()
    {
        AvaloniaXamlLoader.Load(this);

        // After the load, so the theme App.axaml creates is there to register
        Services = BuildServices();
    }

    public override void OnFrameworkInitializationCompleted()
    {
        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        {
            desktop.MainWindow = new MainWindow
            {
                DataContext = new MainViewModel(),
            };
        }
            desktop.MainWindow = new MainWindow { DataContext = Services.GetRequiredService<MainWindowViewModel>() };

        base.OnFrameworkInitializationCompleted();
    }

    private static IServiceProvider BuildServices()
    {
        var services = new ServiceCollection();

        services.AddSingleton(DefaultTheme.Current);
        services.AddSingleton<MainWindowViewModel>();

        return services.BuildServiceProvider();
    }
}
    Why IServiceHost mattersImplementing IServiceHost lets Design.DataContext="{DesignContext}" in your XAML views resolve the real MainWindowViewModel straight from this container in the designer — no separate design-time mock classes required.

Phase 4 · ViewModel Logic

Flesh out MainWindowViewModel

Add the greeting text and three live theme commands using AngelSix.Mvvm's inline cached Command(...) helper.

  1. With the theme injected into our ViewModel, we add the greeting text and the Light/Dark and Bigger/Smaller commands that drive live theme changes.

    ViewModels/MainWindowViewModel.cs
    using System;
using AngelSix.Mvvm;
using AngelSix.Themes.Default;

namespace AvaloniaThemeLab.GettingStarted.ViewModels;

public sealed partial class MainWindowViewModel(DefaultTheme theme) : ViewModelBase
{
    #region Properties

    public DefaultTheme Theme { get; } = theme;

    public string Greeting => "Welcome to the default theme";

    #endregion Properties

    #region Commands

    public IRelayCommand ToggleDarkCommand => Command(() => Theme.IsDark = !Theme.IsDark);

    public IRelayCommand GrowCommand => Command(() => Theme.BaseSize += 0.25);

    public IRelayCommand ShrinkCommand => Command(() => Theme.BaseSize = Math.Max(0.5, Theme.BaseSize - 0.25));

    #endregion Commands
}

    Changing Theme.IsDark flips the entire light/dark palette live; changing Theme.BaseSize scales every spacing, font size, radius and control height ladder across the window automatically.

Phase 5 · MainWindow View

Write MainWindow.axaml using only layout panels and theme tokens

No hard-coded colors, no pixel spacing literals, and no UI logic in code-behind. Every button and text block is drawn by the default theme.

  1. Now we replace the template's starter text box with our themed layout so you can see typography tokens, live mode/scale buttons, and semantic accents in action.

    Add the two theme namespaces (theme: and size:), switch to Design.DataContext="{DesignContext}" for live design-time preview, and replace the starter text block with the theme buttons and accented actions.

    Views/MainWindow.axaml
    <Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:vm="using:AvaloniaThemeLab.GettingStarted.ViewModels"
        xmlns:theme="using:AngelSix.ThemeEngine.Generated"
        xmlns:size="using:AngelSix.ThemeEngine.Sizes"

        xmlns:mc="http://schemas.openxmlformats.org/markup-compatibility/2006"

        mc:Ignorable="d" d:DesignWidth="560" d:DesignHeight="320"

        x:DataType="vm:MainWindowViewModel"

Phase 6 · Build & Run

Build the solution and launch the app

The first build also writes the theme engine's editor snippets for Rider and VS Code.

  1. We build the solution first to make sure the Theme Engine's source generators emitted all the XAML extensions cleanly with zero errors.

    dotnet build AvaloniaThemeLab.GettingStarted.sln

    This compiles the app and writes the engine's snippets into AvaloniaThemeLab.GettingStarted.sln.DotSettings (Rider) and .vscode (VS Code). If Rider was already open, use File → Reload All from Disk to load the new snippets.

  2. Finally, we launch the app so you can click Dark mode, Bigger, and Smaller and watch the entire window react live.

    dotnet run --project AvaloniaThemeLab.GettingStarted

    Try clicking Dark mode, Bigger and Smaller — watch the background, text, spacing, font sizes and the Save (Primary) / Delete (Destructive) buttons update live.

You seeCause and fix

Phase 7 · Optional next step

Extend the default theme

<DefaultTheme /> gets you running in minutes. When your app needs its own brand accent, custom icon tokens, or token overrides without forking the library, subclass DefaultTheme into your own AppTheme.

7.1 Add a custom icon gallery

Create Theme/AppIconGallery.cs inheriting from ThemeIconGallery. Every built-in icon from DefaultTheme stays intact while your new properties become typed XAML markup extensions (such as {icons:Sparkle}).

Theme/AppIconGallery.csNew file
using AngelSix.ThemeEngine;
using AngelSix.Themes.Default;

namespace MyApp.Theme;

/// <summary>
/// Custom icon gallery extending <see cref="ThemeIconGallery"/> with app-specific glyphs.
/// Every built-in icon from the default theme is inherited automatically.
/// </summary>
[IconGallery]
public partial class AppIconGallery : ThemeIconGallery
{
    /// <summary>Four-point sparkle glyph, available in XAML as <c>{icons:Sparkle}</c>.</summary>
    public virtual string Sparkle =>
        "M 12 2 L 14.4 9.6 L 22 12 L 14.4 14.4 L 12 22 L 9.6 14.4 L 2 12 L 9.6 9.6 Z";
}

7.2 Subclass DefaultTheme

Create Theme/AppTheme.cs marked with [Theme] and point Icons at your gallery. Because it inherits from DefaultTheme, you can also override any seed color or size ladder right here.

Theme/AppTheme.csNew file
using AngelSix.ThemeEngine;
using AngelSix.Themes.Default;

namespace MyApp.Theme;

/// <summary>
/// Custom starter theme extending <see cref="DefaultTheme"/> and attaching <see cref="AppIconGallery"/>.
/// Override any token, seed color, or control file here without forking the default theme.
/// </summary>
[Theme]
public sealed partial class AppTheme : DefaultTheme
{
    #region Properties

    /// <inheritdoc />
    public override ThemeIconGallery Icons { get; } = new AppIconGallery();

    #endregion Properties
}

7.3 Swap AppTheme into App & use your icon

Point App.axaml at <local:AppTheme />, register AppTheme.Current in App.axaml.cs, and attach {icons:Sparkle} to a button.

App.axaml
<Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:local="using:MyApp.Theme"
             x:Class="MyApp.App"
             RequestedThemeVariant="Default">
    <Application.Styles>
        <DefaultTheme />
        <local:AppTheme />
    </Application.Styles>
</Application>
App.axaml.cs
using AngelSix.Mvvm;
using AngelSix.Themes.Default;
using MyApp.Theme;
// ... inside BuildServices()
services.AddSingleton(DefaultTheme.Current);
services.AddSingleton(AppTheme.Current);
Views/MainWindow.axaml
