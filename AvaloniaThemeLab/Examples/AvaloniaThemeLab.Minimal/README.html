A Theme From Scratch

Zero built-in styles: build a warm stone & emerald Avalonia theme from scratch on ThemeBase with four color seeds, four size ladders, and two control templates.

Overview

What you are building

A complete custom Avalonia theme built directly on ThemeBase — without DefaultTheme or FluentTheme. You will define four custom seed colors (warm stone surface, charcoal neutral, forest emerald primary, terracotta danger), four size ladders, and just two control templates (Window and Button), then render a live Theme Specimen Card.

Phase 1 · Project & Packages

Create a blank Avalonia app without any built-in theme

Notice the key difference from Getting Started: we install AngelSix.ThemeEngine, AngelSix.Mvvm, and DI — and intentionally do not install AngelSix.Themes.Default.

  1. First we scaffold a fresh Avalonia MVVM app and solution to serve as our blank slate.

    dotnet new avalonia.mvvm -n MyMinimalApp
dotnet new sln -n MyMinimalApp --format sln
dotnet sln MyMinimalApp.sln add MyMinimalApp/MyMinimalApp.csproj

  2. Because we're building a theme completely from scratch with AngelSix.Mvvm, we strip out FluentTheme (or Fluent2Theme on newer Avalonia templates), the template's Inter font package, and CommunityToolkit.Mvvm so zero built-in styles or conflicting MVVM types remain.

    dotnet remove MyMinimalApp package Avalonia.Themes.Fluent2
dotnet remove MyMinimalApp package Avalonia.Themes.Fluent
dotnet remove MyMinimalApp package Avalonia.Fonts.Inter
dotnet remove MyMinimalApp package CommunityToolkit.Mvvm

    Newer Avalonia 12 templates reference Avalonia.Themes.Fluent2 while older ones reference Avalonia.Themes.Fluent — remove whichever is in your .csproj. Removing CommunityToolkit.Mvvm ensures ViewModelBase and ObservableObject resolve to AngelSix.Mvvm.

  3. Now we install only AngelSix.ThemeEngine, AngelSix.Mvvm, and DI — deliberately skipping DefaultTheme so every token and control style is ours.

    dotnet add MyMinimalApp package AngelSix.ThemeEngine
dotnet add MyMinimalApp package AngelSix.Mvvm
dotnet add MyMinimalApp package Microsoft.Extensions.DependencyInjection
    No built-in theme libraryBecause we did not install AngelSix.Themes.Default or keep FluentTheme, Avalonia starts with zero control templates — every pixel you see comes from the theme class and two control files you write next.

  4. Next we tidy up the template by deleting the unused ViewModelBase and MainViewModel, dropping .WithInterFont(), and pointing ViewLocator at AngelSix.Mvvm.ViewModelBase.

    Delete the template's ViewModels/ViewModelBase.cs and ViewModels/MainViewModel.cs, remove .WithInterFont() from Program.cs, and update ViewLocator.cs to import AngelSix.Mvvm so data is ViewModelBase matches our AngelSix.Mvvm.ViewModelBase.

    ViewLocator.cs
    using System;
using AngelSix.Mvvm;
using Avalonia.Controls;
using Avalonia.Controls.Templates;
using MyMinimalApp.ViewModels;

namespace MyMinimalApp;

public class ViewLocator : IDataTemplate
{
    public Control? Build(object? param)
    {
        if (param is null) return null;
        var name = param.GetType().FullName!.Replace("ViewModel", "View", StringComparison.Ordinal);
        var type = Type.GetType(name);
        if (type != null) return (Control)Activator.CreateInstance(type)!;
        return new TextBlock { Text = "Not Found: " + name };
    }

    public bool Match(object? data) => data is ViewModelBase;
}

Phase 2 · One C# Theme Class

Write Theme/MinimalTheme.cs on ThemeBase

Everything in your design system lives in one C# class marked with [Theme]. The source generator turns its seeds, stage defaults, and size ladders into live XAML markup extensions ({color:…}, {size:…}, {theme:…}).

  1. Before we can style any controls, we create MinimalTheme on ThemeBase to define our four custom seed colors, semantic stage defaults, and size ladders.

    Theme/MinimalTheme.csNew file
    using AngelSix.Mvvm;
using AngelSix.ThemeEngine;
using Avalonia;
using Avalonia.Media;

namespace MyMinimalApp.Theme;

/// <summary>A custom theme built from scratch on <see cref="ThemeBase"/> with warm stone surfaces and an emerald/terracotta palette.</summary>
[Theme(FallbackHue = "Neutral")]
public partial class MinimalTheme : ThemeBase
{
    #region Defaults

    // What the theme falls back to: a plain reuse of a seed first, then the stage each part of a control defaults to

    /// <summary>The window canvas: the surface seed, or its DarkSeed in the dark palette.</summary>
    public virtual Color WindowBackground => SurfaceSeed;

    // Surfaces
    [StageDefault] internal virtual Stage CardBackground => Stage.Light10;

    [StageDefault] internal virtual Stage ButtonBackground => Stage.Light9;

    [StageDefault] internal virtual Stage ButtonHoverBackground => Stage.Light7;

    [StageDefault] internal virtual Stage ButtonPressedBackground => Stage.Light5;

    // Text
    [StageDefault(PinHue = "Neutral")] internal virtual Stage WindowText => Stage.Dark9;

    [StageDefault(PinHue = "Neutral")] internal virtual Stage MutedText => Stage.Dark2;

    [StageDefault] internal virtual Stage ButtonText => Stage.Dark9;

    // Lines
    [StageDefault] internal virtual Stage CardBorder => Stage.Light3;

    [StageDefault] internal virtual Stage ButtonBorder => Stage.Light1;

    #endregion Defaults

    #region Seeds

    [AccentHue, ColorRamp(HueAware = true, DarkSeed = "#DCD9D0")]
    [Observable] public virtual partial Color AccentNeutral { get; set; } = Color.Parse("#232625");

    [AccentHue, ColorRamp(HueAware = true)]
    [Observable] public virtual partial Color AccentPrimary { get; set; } = Color.Parse("#1B7F5C");

    [AccentHue, ColorRamp(HueAware = true)]
    [Observable] public virtual partial Color AccentDanger { get; set; } = Color.Parse("#C84B31");

    [AccentHue, ColorRamp(DarkSeed = "#171A19")]
    [Observable] public virtual partial Color AccentSurface { get; set; } = Color.Parse("#F4F1EA");

    #endregion Seeds

    #region Sizes

    // Every ladder grows from ThemeBase's BaseSize

    [SizeScale(Multipliers = [4, 8, 12, 20], Labels = ["Sm", "Md", "Lg", "Xl"])]
    public virtual double Spacing => BaseSize;

    [SizeScale(Multipliers = [12, 14, 22], Labels = ["Sm", "Md", "Lg"])]
    public virtual double FontSize => BaseSize;

    [SizeScale(Multipliers = [6, 12], Labels = ["Sm", "Md"], Types = [typeof(CornerRadius)], TypeSuffixes = [""])]
    public virtual double Radius => BaseSize;

    [SizeScale(Multipliers = [1, 2], Labels = ["Sm", "Md"], Types = [typeof(Thickness)], TypeSuffixes = [""], Floor = 1)]
    public virtual double Thickness => BaseSize;

    #endregion Sizes

    [FontWeights(Weights = [FontWeight.Normal, FontWeight.SemiBold], Labels = ["Regular", "SemiBold"])]
    public virtual FontFamily FontFamily => AngelSix.ThemeEngine.Fonts.ThemeFonts.Inter;
}
    How the three regions work together
    • Seeds ([AccentHue, ColorRamp]): four colors generate full light & dark shade ramps plus AccentNeutralBrush, AccentPrimaryBrush, AccentDangerBrush.
    • Defaults ([StageDefault]): map semantic roles (CardBackground, ButtonHoverBackground, MutedText) to stops on whichever hue is active via theme:Accent.Kind.
    • Sizes ([SizeScale]): multiply BaseSize into typed Spacing*, FontSize*, Radius*, and Thickness* tokens.

Phase 3 · Control Templates

Style Window and Button from scratch

The theme engine automatically discovers and loads every .axaml resource dictionary inside Controls/ — no manual ResourceInclude wiring needed.

  1. Without a built-in theme, an Avalonia Window has no template and draws blank — so our first control file gives Window its background, ink, and content host.

    Without a built-in theme, an Avalonia Window has no ControlTemplate and renders blank. Give it a simple ContentPresenter bound to your theme's WindowBackgroundBrush, WindowTextBrush, and FontFamily.

    Controls/Window.axamlNew file
    <ResourceDictionary xmlns="https://github.com/avaloniaui"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
                    xmlns:theme="using:AngelSix.ThemeEngine.Generated"
                    xmlns:color="using:AngelSix.ThemeEngine.Colors"
                    xmlns:size="using:AngelSix.ThemeEngine.Sizes">

  <!-- Without a theme a Window has no template and shows nothing -->
  <ControlTheme x:Key="{x:Type Window}" TargetType="Window">
    <Setter Property="Background" Value="{color:WindowBackgroundBrush}" />
    <Setter Property="Foreground" Value="{color:WindowTextBrush}" />
    <Setter Property="FontFamily" Value="{theme:FontFamily}" />
    <Setter Property="FontSize" Value="{size:FontSizeMd}" />
    <Setter Property="Template">
      <ControlTemplate>
        <ContentPresenter Name="PART_ContentPresenter"
                          Background="{TemplateBinding Background}"
                          Content="{TemplateBinding Content}"
                          ContentTemplate="{TemplateBinding ContentTemplate}" />
      </ControlTemplate>
    </Setter>
  </ControlTheme>

</ResourceDictionary>

  2. Next we style Button using our stage defaults so neutral, Primary, and Danger buttons (plus hover and pressed states) all work automatically.

    Because every color is a [StageDefault], a single ControlTheme handles neutral, Primary, and Danger buttons — including hover and pressed states in both Light and Dark modes.

    Controls/Button.axamlNew file
    <ResourceDictionary xmlns="https://github.com/avaloniaui"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
                    xmlns:theme="using:AngelSix.ThemeEngine.Generated"
                    xmlns:color="using:AngelSix.ThemeEngine.Colors"
                    xmlns:size="using:AngelSix.ThemeEngine.Sizes">

  <!-- Every color is a stage default, so it follows the button's Accent.Kind and the theme's IsDark -->
  <ControlTheme x:Key="{x:Type Button}" TargetType="Button">
    <Setter Property="Background" Value="{color:ButtonBackgroundBrush}" />
    <Setter Property="Foreground" Value="{color:ButtonTextBrush}" />
    <Setter Property="BorderBrush" Value="{color:ButtonBorderBrush}" />
    <Setter Property="BorderThickness" Value="{size:ThicknessSm}" />
    <Setter Property="CornerRadius" Value="{size:RadiusSm}" />
    <Setter Property="Padding" Value="{size:Edges {size:SpacingLg}, {size:SpacingSm}}" />
    <Setter Property="FontFamily" Value="{theme:FontFamily}" />
    <Setter Property="FontSize" Value="{size:FontSizeMd}" />
    <Setter Property="Template">
      <ControlTemplate>
        <ContentPresenter Name="PART_ContentPresenter"
                          Background="{TemplateBinding Background}"
                          BorderBrush="{TemplateBinding BorderBrush}"
                          BorderThickness="{TemplateBinding BorderThickness}"
                          CornerRadius="{TemplateBinding CornerRadius}"
                          Padding="{TemplateBinding Padding}"
                          Content="{TemplateBinding Content}"
                          ContentTemplate="{TemplateBinding ContentTemplate}" />
      </ControlTemplate>
    </Setter>

    <Style Selector="^:pointerover">
      <Setter Property="Background" Value="{color:ButtonHoverBackgroundBrush}" />
    </Style>

    <Style Selector="^:pressed">
      <Setter Property="Background" Value="{color:ButtonPressedBackgroundBrush}" />
    </Style>
  </ControlTheme>

</ResourceDictionary>

Phase 4 · App, DI & ViewModel

Activate MinimalTheme and wire live commands

Load <local:MinimalTheme /> in App.axaml, inject MinimalTheme.Current into MainWindowViewModel, and expose Light/Dark, scale, and reset commands.

  1. Now that our theme and two control files exist, we swap Fluent2Theme (or FluentTheme on older templates) out of App.axaml and plug in MinimalTheme.

    Added / changedRemoved
    App.axaml
    <Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:local="using:MyMinimalApp"
             xmlns:theme="using:MyMinimalApp.Theme"
             x:Class="MyMinimalApp.App"
             RequestedThemeVariant="Default">
    <Application.DataTemplates>
        <local:ViewLocator/>
    </Application.DataTemplates>
    <Application.Styles>
        <Fluent2Theme /> <!-- or <FluentTheme /> on older templates -->
        <theme:MinimalTheme />
    </Application.Styles>
</Application>

  2. Next we create MainWindowViewModel to receive MinimalTheme and expose our Light/Dark, A+/A− scaling, and Reset commands.

    ViewModels/MainWindowViewModel.csNew file
    using System;
using AngelSix.Mvvm;
using MyMinimalApp.Theme;

namespace MyMinimalApp.ViewModels;

public sealed partial class MainWindowViewModel([Property] MinimalTheme theme) : ViewModelBase
{
    #region Commands

    public IRelayCommand ToggleDarkCommand => Command(() => Theme.IsDark = !Theme.IsDark);

    public IRelayCommand GrowCommand => Command(() => Theme.BaseSize = Math.Min(1.5, Math.Round(Theme.BaseSize + 0.1, 2)));

    public IRelayCommand ShrinkCommand => Command(() => Theme.BaseSize = Math.Max(0.75, Math.Round(Theme.BaseSize - 0.1, 2)));

    public IRelayCommand ResetCommand => Command(() =>
    {
        Theme.IsDark = false;
        Theme.BaseSize = 1.0;
    });

    #endregion Commands
}

  3. With the ViewModel ready, we wire MinimalTheme.Current and MainWindowViewModel into DI in App.axaml.cs so both the app and designer resolve them.

    Added / changedRemoved
    App.axaml.cs
    using System;
using AngelSix.Mvvm;
using Avalonia;
using Avalonia.Controls.ApplicationLifetimes;
using Avalonia.Markup.Xaml;
using MyMinimalApp.Theme;
using MyMinimalApp.ViewModels;
using MyMinimalApp.Views;
using Microsoft.Extensions.DependencyInjection;

namespace MyMinimalApp;

public partial class App : Application
public partial class App : Application, IServiceHost
{
    public IServiceProvider Services { get; private set; } = null!;

    public override void Initialize()
    {
        AvaloniaXamlLoader.Load(this);
        Services = BuildServices();
    }

    public override void OnFrameworkInitializationCompleted()
    {
        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
            desktop.MainWindow = new MainWindow { DataContext = new MainViewModel() };
            desktop.MainWindow = new MainWindow { DataContext = Services.GetRequiredService<MainWindowViewModel>() };

        base.OnFrameworkInitializationCompleted();
    }

    private static IServiceProvider BuildServices()
    {
        var services = new ServiceCollection();
        services.AddSingleton(MinimalTheme.Current);
        services.AddSingleton<MainWindowViewModel>();
        return services.BuildServiceProvider();
    }
}

Phase 5 · Specimen Card UI

Build the live palette & scale card in Views/MainWindow.axaml

Show off every token you just defined: your four custom color seeds as live swatches, A− / 1.00× / A+ scale controls, a Light/Dark toggle, and Primary / Danger accented buttons.

  1. Now we build our Theme Specimen Card in MainWindow.axaml to display our four live seed swatches, scale readout, and accented buttons.

Phase 6 · Build & Run

Launch your custom theme

  1. Everything is in place — let's build and run the app to see our from-scratch theme rendered.

    dotnet run --project MyMinimalApp/MyMinimalApp.csproj

  2. Finally, click Dark mode, A+, A−, and Reset to watch your custom seeds and size ladders recalculate the entire window live.

    • Click Dark mode — watch the warm ivory canvas flip to deep charcoal and all card borders, labels, and emerald/terracotta button states invert cleanly.
    • Click A+ and A− — watch every font size, spacing gap, corner radius, and card width scale proportionally from BaseSize.
    • Click Reset to snap back to Light mode at 1.00×.
