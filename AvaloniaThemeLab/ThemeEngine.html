Introduction

A theme is one C# class.

The theme engine replaces Avalonia's resource-key theming with typed tokens, generated XAML extensions and automatic file loading. You describe a theme once; the engine does the wiring.

Plain AvaloniaTheme engine
Theme values✕untyped string keys✓typed C# tokens, with IntelliSense
A typo✕renders nothing at run time✓fails the build
Control files✕listed by hand, kept in step✓found at build time
Sizes✕literals repeated everywhere✓grow from one BaseSize
Colours✕every shade chosen by hand✓one seed per hue
Accent colours✕a copy of each style per colour✓one style, every hue
Dark mode✕a second set of resources✓the same seeds, one switch

Getting started

From a new app to a themed app

Six steps, one package and one line of XAML. You need the .NET 10 SDK and the Avalonia templates (dotnet new install Avalonia.Templates).

  1. dotnet new avalonia.mvvm -n MyApp
    A standard Avalonia 12 MVVM app, using Fluent.
  2. dotnet remove MyApp package Avalonia.Themes.Fluent
    Nothing will use it once the theme is in.
  3. dotnet add MyApp package AngelSix.Themes.Default
    This brings the engine and AngelSix.Mvvm with it.
  4. <Application.Styles>
    <DefaultTheme />
</Application.Styles>
    It replaces <FluentTheme />. No xmlns line is needed: DefaultTheme lives in Avalonia's own namespace.
  5. dotnet build MyApp
    The build also writes the engine's editor snippets for Rider and VS Code (see Editor snippets).
  6. dotnet run --project MyApp
    Every control now draws with the default theme. Keep .WithInterFont() in Program.cs: the theme's font is Inter.

Using the default theme

Hues, light and dark, and your own XAML

The default theme works with no setup. These are the things you reach for next.

Give a control a hue

<Button Content="Save" theme:Accent.Kind="Primary" />
<Button Content="Delete" theme:Accent.Kind="Destructive" />

Hues: Neutral, Primary, Success, Warning, Favourite, Error, Info, Destructive, Subtle. Accent.Kind inherits, so setting it on a panel tints everything inside.

Use the theme's tokens

Type themexml and Tab on a root element to declare the namespaces, then read any token:

<Border Padding="{size:Edges {size:SpacingLg}}"
        CornerRadius="{size:RadiusSm}"
        Background="{color:AccentBrush Light9}">
  <TextBlock Text="Hello" FontSize="{size:FontSizeLg}" />
</Border>

Change it at run time

var theme = DefaultTheme.Current;
theme.IsDark = true;         // the whole app turns dark
theme.BaseSize = 1.25;       // every size grows by a quarter
theme.AccentPrimary = Color.Parse("#7C4DFF");   // the whole Primary ramp follows
theme.ResetToDefaults();

With dependency injection, register it once: services.AddSingleton(DefaultTheme.Current);

Make it yours without forking

Subclass DefaultTheme and change only what differs — a hue, a token, or one control. See Extend the default theme.

Creating your own theme

Extend the default theme

The middle path between using the default theme and writing one from nothing: keep every control it styles, and change only the values — or the one control — your look needs. You subclass DefaultTheme; the engine does the rest.

  1. Steps 1–5 of Getting started: a new app, no Fluent, the default theme referenced and included. You already have a fully styled app.
  2. dotnet add MyApp package AngelSix.ThemeEngine
    For its source generator, which turns your subclass into XAML extensions.
  3. A new C# file deriving from DefaultTheme. Add a hue, override a token, or change a seed — everything else is inherited: 
    [Theme(FallbackHue = "Neutral")]
public partial class BrandTheme : DefaultTheme
{
    [AccentHue, ColorRamp(HueAware = true)]
    [Observable] public virtual partial Color AccentBrand { get; set; } = Color.Parse("#7C4DFF");
}
  4. <Application ... xmlns:local="using:MyApp.Theme">
  <Application.Styles>
    <local:BrandTheme />
  </Application.Styles>
</Application>
    Register BrandTheme.Current in place of DefaultTheme.Current if you use dependency injection.
  5. Add Controls/Button.axaml in your project to override just that control; every other control keeps the default theme's file. There is no list to update.
  6. The whole app draws with the default theme plus your changes. A theme that extends one from another project gets its own hue property, named after the class: theme:BrandAccent.Kind="Brand". It accepts the new hue and every inherited one. Roles are internal, so they can only be changed in the theme's own project.
Worked exampleExamples/AvaloniaThemeLab.ThemePlayground is exactly this: a BrandTheme : DefaultTheme that adds one brand hue on top of the full default control set.
When to go from scratch insteadIf your look owes nothing to the default theme — different control shapes, a different token vocabulary — start from ThemeBase and write your own control files: A theme from scratch.

Creating your own theme

A theme from scratch

For a look that owes nothing to the default theme. You write the tokens and the control files; the engine does the rest. If you only need to change values or one control, extend the default theme instead.

  1. Steps 1 and 2 of Getting started.
  2. dotnet add MyApp package AngelSix.ThemeEngine
  3. Type themeclass and Tab in a new C# file. It gives a working theme to edit: 
    [Theme(FallbackHue = "Neutral")]
public partial class MyTheme : ThemeBase
{
    [AccentHue, ColorRamp(HueAware = true, DarkSeed = "#D1D1D1")]
    [Observable] public virtual partial Color AccentNeutral { get; set; } = Color.Parse("#2E2E2E");

    [AccentHue, ColorRamp(HueAware = true)]
    [Observable] public virtual partial Color AccentPrimary { get; set; } = Color.Parse("#2F6FEB");

    [AccentHue, ColorRamp(DarkSeed = "#1E1E1E")]
    [Observable] public virtual partial Color AccentSurface { get; set; } = Color.Parse("#FAFAFA");

    [SizeScale(Multipliers = [4, 8, 12, 16])]
    public virtual double Spacing => BaseSize;
}
  4. <Application ... xmlns:local="using:MyApp.Theme">
  <Application.Styles>
    <local:MyTheme />
  </Application.Styles>
</Application>
  5. Add Controls/Button.axaml, type themecontrol and Tab. You get the control's preview, its designer preview and a ControlTheme wired to the tokens. There's no list to add it to.
  6. The button draws with your theme. Every other control has no template yet, so it draws nothing: add a file per control as you go.
Worked exampleExamples/AvaloniaThemeLab.Minimal is exactly this: a new app, no Fluent, one small theme with ramps, hues, roles and ladders, and two styled controls.

How it works

What happens after the one line

The engine does its work in two places: at build time, where source generators turn your theme class into XAML extensions and a list of files; and at start-up, where the theme loads that list and registers itself.

BuildGenerators read the theme class and the project's .axaml files
GenerateOne XAML extension per token, plus the list of control files
Start<MyTheme /> creates the theme
LoadThe theme loads its files and registers itself
ResolveEvery {color:…} reads the live theme

1Loading the theme

At build time, a generator reads every .axaml in the theme's project and sorts them by their root element:

  • A ResourceDictionary holding a ControlTheme is a control file.
  • A Styles file with no x:Class is a styles file, for the few rules a ControlTheme can't hold.

It writes both lists into the assembly. Nothing is written into your project.

At start-up, <MyTheme /> constructs the theme. A theme is an Avalonia Styles, so it sits where FluentTheme did. Its constructor:

  1. loads every listed file, from the base theme first, so a derived theme's styles come last and win;
  2. registers itself as the app's active theme, which every XAML token reads from.
The pointAvalonia normally needs a ResourceInclude for every control file, kept in step by hand. Here, adding a control is adding its file; removing one is deleting it.

An app has one theme. Reach it from code with MyTheme.Current, which the engine generates on every theme class.

2Tokens become XAML

Every public property on the theme is a token. The generator gives each one a markup extension, filed by its C# type:

PrefixHoldsExamples
{color:…}Colours and brushes{color:AccentBrush Light10}, {color:TextDefault}
{size:…}Numbers, Thickness, CornerRadius{size:SpacingMd}, {size:RadiusSm}
{theme:…}Everything else{theme:FontFamily}, {theme:StandardAlignmentHorizontal}
{icons:…}Icon geometry{icons:Save}
The pointA token is a real type, so XAML gets IntelliSense, and a typo fails the build instead of rendering nothing. Rename a property and every use is found.

3Live changes

A token in XAML is a binding, not a copied value. Mark a token [Observable] and setting it raises a change; every binding that reads it, or any token computed from it, updates.

[Observable] public virtual partial double HoverScale { get; set; } = 1.05;

The theme implements INotifyPropertyChanged through AngelSix.Mvvm, so a settings screen can bind straight to it: Value="{Binding Theme.BaseSize}". ResetToDefaults() puts every [Observable] token, and every generated scale, back to its declared value.

4Colour: seeds and ramps

A hue is one colour. [ColorRamp] turns that seed into twenty stages: Light1 to Light10 towards the canvas, and Dark1 to Dark10 towards the ink.

Light10seedDark10
  • HueAware = true puts stage N at the same perceived lightness in every hue, so a role keeps its contrast whatever hue a control wears.
  • The light palette's ink is drawn through an InkProfile, so orange reads as rust rather than brown, still from the one seed.
  • IsDark mirrors every ramp for the dark palette. DarkSeed re-centres a ramp on another colour in the dark.
The pointChange one seed and its whole family follows: every stage, light and dark, every control that uses it.

5Hues and roles

[AccentHue] makes a ramp a hue a control can wear. A style reads the control's current hue with {color:AccentBrush}, so one block serves them all:

<Style Selector="^:pointerover /template/ Border#PART_Border">
  <Setter Property="Background" Value="{color:AccentBrush Light8}" />
</Style>

A role names a stage that recurs, so the theme decides it once:

[AccentRole] internal virtual RampStage BorderDefault => RampStage.Light1;

{color:BorderDefault} is then Light1 of whatever hue the control wears. Roles can also follow policies: PinHue (always one hue), BrightStage (a softer stage for a very light seed like yellow), ContrastAgainst (pick light or dark ink against a fill) and focus colours.

6Sizes and ladders

Every size grows from BaseSize, which ThemeBase owns. A ladder turns one multiplier list into a set of tokens:

[SizeScale(Multipliers = [4, 8, 12, 16], Scalable = true)]
public virtual double Spacing => BaseSize;   // SpacingSm, SpacingMd, SpacingLg, SpacingXl, SpacingScale
  • Types also emits a ladder as Thickness or CornerRadius.
  • Floor and Ceiling clamp it, such as a border that never drops below one pixel.
  • Scalable adds {Name}Scale, to resize one ladder on its own.

For the odd size that isn't a token, scale from the base: Width="{size:Scaled 320}" is 320 × BaseSize. Compose paddings with {size:Edges {size:SpacingXl}, {size:SpacingLg}}.

The pointSet BaseSize to 2 and the whole interface zooms exactly, with nothing hard-coded left behind.

7Light and dark

IsDark switches the app. theme:ThemeRegion.IsDark draws one part of a window in the other palette, from the same theme instance:

<Border theme:ThemeRegion.IsDark="True">
  <!-- everything in here draws dark -->
</Border>

8Icons

Point a gallery at a folder of .svg files and each becomes a token:

[IconGallery(SvgFolder = "Icons/Svg")]
public partial class MyIcons { }

public override MyIcons Icons => new();   // in the theme

Icons/Svg/Save.svg is then {icons:Save}. Adding an icon is adding a file.

9AngelSix.Mvvm

The engine is built on AngelSix.Mvvm, and your app can use it too. Everything is generated; nothing is written by hand.

public partial class MainViewModel(MyTheme theme) : ObservableObject
{
    [Observable] public partial string Title { get; set; } = "";

    [Command] private void ToggleDark() => theme.IsDark = !theme.IsDark;   // ToggleDarkCommand
}
  • [NotifyPropertyChanged] gives change notification to a class that already has a base. ThemeBase uses it.
  • Design.DataContext="{DesignContext}" gives the designer the view model named by the view's x:DataType, from the app's services. The App class implements IServiceHost.

10Previews

Each control file carries a {Name}Preview template and a Design.PreviewWith that shows it through LightDarkPreview, side by side in both palettes. theme:Preview.State="Hover" pins a control in a state, so hover, pressed and focused are visible at once. The playground's gallery shows the same templates.

Avalonia knowledge

Things Avalonia does that catch you out

Not the engine's rules, but Avalonia's. Each one cost real time to find; each has a one-line fix.

1Style precedence

When more than one thing sets a property, Avalonia picks by priority, and the lowest number wins. The band is decided first: no selector, however specific, beats a lower band.

-1Animationalways winsa running Animation or Transition
0LocalValueset on the element<Border BorderThickness="2" />, or any {Binding}
1StyleTrigger:state or .class selector<Style Selector="Border:pointerover">
2Templatea bare TemplateBindingBorderThickness="{TemplateBinding BorderThickness}"
3Styleplain selector<Style Selector="Border">
4Inheritedfrom a parentFontSize set on an ancestor

That is why a :pointerover style (1) can change a template's value (2), and a plain style (3) is the baseline both start from.

The trap: a wrapped TemplateBinding

Priority comes from the outermost binding assigned to the property, not from anything nested inside it.

✓ Template (2): a state can override it

BorderThickness="{TemplateBinding BorderThickness}"

✕ LocalValue (0): nothing can override it

BorderThickness="{size:Edges {TemplateBinding BorderThickness}}"

Wrapped in any other extension, the TemplateBinding is just a source; the property gets the outer binding, set on the element, so LocalValue. A :pointerover style then does nothing, and even a literal 0 in it is ignored. That's the tell.

The fix: move the value off the element and into a plain style. Then the default is Style (3), the state is StyleTrigger (1), and the state wins.

<!-- default, from a style -->
<Style Selector="^ /template/ RepeatButton">
  <Setter Property="BorderThickness" Value="{size:Edges {TemplateBinding BorderThickness}}" />
</Style>
<!-- the state now wins -->
<Style Selector="^:left /template/ RepeatButton">
  <Setter Property="BorderThickness" Value="0" />
</Style>

Writing your own extension for use in templates? Set Priority = BindingPriority.Template on the binding it returns, so it behaves like a real TemplateBinding when used inline.

2ControlTheme limits

A ControlTheme styles one control and its template. It can't hold a style that reaches other controls through a child or descendant selector; Avalonia throws "ControlTheme style may not directly contain a child or descendent selector".

The fix: put that rule in a plain Styles file in the theme project. The engine loads it with the control files, so there is still nothing to register.

3Transitions that never stop

A transition starts when its property's value changes, and Avalonia compares brushes and transforms by object, not by value. If a binding builds a new brush every time it's read, the transition re-reads it as it starts, sees a "new" value, and starts again, until the stack overflows. Nothing reports it; the app just dies.

The fix: hand back the same object for the same value. The engine does this for every brush and scale transform it produces, so tokens are safe; a converter of your own that feeds a transitioned property needs the same care.
