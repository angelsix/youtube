Introduction

A theme is one C# class.

The theme engine replaces Avalonia's resource-key theming with typed tokens, generated XAML extensions and automatic file loading. You describe a theme once; the engine does the wiring.

Plain AvaloniaTheme engine
Theme values✕untyped string keys✓typed C# tokens, with IntelliSense
A typo✕renders nothing at run time✓fails the build
Control files✕listed by hand, kept in step✓found at build time
Sizes✕literals repeated everywhere✓grow from one BaseSize
Colors✕every shade chosen by hand✓one seed per hue
Accent colors✕a copy of each style per color✓one style, every hue
Dark mode✕a second set of resources✓the same seeds, one switch

How it works

What happens after the one line

The engine does its work in two places: at build time, where source generators turn your theme class into XAML extensions and a list of files; and at start-up, where the theme loads that list and registers itself.

BuildGenerators read the theme class and the project's .axaml files
GenerateOne XAML extension per token, plus the list of control files
Start<MyTheme /> creates the theme
LoadThe theme loads its files and registers itself
ResolveEvery {color:…} reads the live theme

1Loading the theme

At build time, a generator reads every .axaml in the theme's project and sorts them by their root element:

  • A ResourceDictionary holding a ControlTheme is a control file.
  • A Styles file with no x:Class is a styles file, for the few rules a ControlTheme can't hold.

It writes both lists into the assembly. Nothing is written into your project.

At start-up, <MyTheme /> constructs the theme. A theme is an Avalonia Styles, so it sits where Fluent2Theme / FluentTheme did. Its constructor:

  1. loads every listed file, from the base theme first, so a derived theme's styles come last and win;
  2. registers itself as the app's active theme, which every XAML token reads from.
The pointAvalonia normally needs a ResourceInclude for every control file, kept in step by hand. Here, adding a control is adding its file; removing one is deleting it.

An app has one theme. Reach it from code with MyTheme.Current, which the engine generates on every theme class.

2Tokens become XAML

Every public property on the theme is a token. The generator gives each one a markup extension, filed by its C# type:

PrefixHoldsExamples
{color:…}Colors and brushes{color:AccentBrush Light10}, {color:TextDefault}
{size:…}Numbers, Thickness, CornerRadius{size:SpacingMd}, {size:RadiusSm}
{theme:…}Everything else{theme:FontFamily}, {theme:StandardAlignmentHorizontal}
{icons:…}Icon geometry{icons:Save}
The pointA token is a real type, so XAML gets IntelliSense, and a typo fails the build instead of rendering nothing. Rename a property and every use is found.

3Live changes

A token in XAML is a binding, not a copied value. Mark a token [Observable] and setting it raises a change; every binding that reads it, or any token computed from it, updates.

// Quick: type aatoken, then Tab
[Observable] public virtual partial double HoverScale { get; set; } = 1.05;

The theme implements INotifyPropertyChanged through AngelSix.Mvvm, so a settings screen can bind straight to it: Value="{Binding Theme.BaseSize}". ResetToDefaults() puts every [Observable] token, and every generated scale, back to its declared value.

4Color: seeds and ramps

A hue is one color. [ColorRamp] turns that seed into twenty stages: Light1 to Light10 towards the canvas, and Dark1 to Dark10 towards the ink.

Light10seedDark10
  • HueAware = true puts stage N at the same perceived lightness in every hue, so a role keeps its contrast whatever hue a control wears.
  • The light palette's ink is drawn through an InkProfile, so orange reads as rust rather than brown, still from the one seed.
  • IsDark mirrors every ramp for the dark palette. DarkSeed re-centres a ramp on another color in the dark.
The pointChange one seed and its whole family follows: every stage, light and dark, every control that uses it.

5Hues and roles

[AccentHue] makes a ramp a hue a control can wear. A style reads the control's current hue with {color:AccentBrush}, so one block serves them all:

<!-- Quick: type aastyle, then Tab -->
<Style Selector="^:pointerover /template/ Border#PART_Border">
  <Setter Property="Background" Value="{color:AccentBrush Light8}" />
</Style>

A stage default names a stage that recurs, so the theme decides it once (included in the aatheme snippet, or standalone via aastage):

[StageDefault] protected internal virtual Stage BorderDefault => Stage.Light1;

{color:BorderDefault} is then Light1 of whatever hue the control wears. Stage defaults can also follow policies: PinHue (always one hue), BrightStage (a softer stage for a very light seed like yellow), ContrastStage / AlternateStage (pick light or dark ink against a fill) and focus colors. DefaultTheme also provides Accents and an observable DefaultAccent so accent pickers need zero hand-rolled palettes.

6Sizes and ladders

Every size grows from BaseSize, which ThemeBase owns. A ladder turns one multiplier list into a set of tokens:

// Quick: type aaladder, then Tab
[SizeScale(Multipliers = [4, 8, 12, 16], Scalable = true)]
public virtual double Spacing => BaseSize;   // SpacingSm, SpacingMd, SpacingLg, SpacingXl, SpacingScale
  • Types also emits a ladder as Thickness or CornerRadius.
  • Floor and Ceiling clamp it, such as a border that never drops below one pixel.
  • Scalable adds {Name}Scale, to resize one ladder on its own.

For the odd size that isn't a token, scale from the base: Width="{size:Scaled 320}" is 320 × BaseSize. Compose paddings with {size:Edges {size:SpacingXl}, {size:SpacingLg}}.

The pointSet BaseSize to 2 and the whole interface zooms exactly, with nothing hard-coded left behind.

7Regions: light/dark, scale, and automatic corners

IsDark (and its inverse IsLight) switches the app — both are directly bindable in XAML via {theme:IsDark} and {theme:IsLight}, respecting scoped regions. theme:ThemeRegion overrides the palette or size scale for any subtree, from the same theme instance:

<Border theme:ThemeRegion.IsDark="True" theme:ThemeRegion.BaseSize="2">
  <!-- everything in here draws dark at 2x scale; nest theme:ThemeRegion.Scale="1.5" to multiply further -->
</Border>

theme:ThemeRegion.BaseSize overrides BaseSize for that subtree and theme:ThemeRegion.Scale multiplies the inherited base size, so every ladder and control template scales crisply in vector space. Painted Borders sitting flush inside a rounded ancestor Border also fit their touched corners concentrically automatically without needing ClipToBounds="True" or manual ConcentricCorners.

8Icons

A gallery is a class of icon paths. Point it at a folder and each drawing becomes a token — .svg files are the format it reads today:

// Quick: type aagallery, then Tab
[IconGallery(SvgFolder = "Icons/Svg")]
public partial class MyIcons { }

public override ThemeIconGallery Icons { get; } = new MyIcons();   // in the theme
MyApp/
└── Icons/
    └── Svg/
        ├── Save.svg    → {icons:Save}
        ├── Star.svg    → {icons:Star}
        └── Trash.svg   → {icons:Trash}

SvgFolder is read from the project folder — where the .csproj sits — and searched recursively. The file's name is the token, so adding an icon is adding a file. Hand-written string properties live beside the generated ones, and a hand-written name wins over a file: that is how you alias (public virtual string DropDown => ChevronDown;) or redraw one icon.

Extending the default themeA gallery there derives from ThemeIconGallery — the type DefaultTheme hands to Icons. Deriving from it is also the gain: every default icon comes with you, your files add to the set, and public override string ChevronDown => "…" redraws one everywhere the theme uses it, its own control templates included:
[IconGallery(SvgFolder = "Icons/Svg")]
public partial class MyIcons : ThemeIconGallery { }

public override ThemeIconGallery Icons { get; } = new MyIcons();   // in the subclass

To render an icon cleanly in XAML without repeating PathIcon, {icons:Lookup …}, Width and Height, use the prefix-free <Icon> control shipped in AngelSix.Themes.Default. It auto-detects a string icon name (resolved live from Theme.Icons), a Geometry (like {icons:Search}), or an IImage, inherits Foreground, and defaults to a square via Size while still allowing independent Width/Height overrides:

<Icon Content="{Binding Icon}" Size="{size:IconSizeSm}" />                     <!-- bound string name -->
<Icon Content="{icons:ArrowDown}" Size="{size:IconSizeSm}" />                 <!-- direct geometry -->
<Icon Content="{icons:Banner}" Width="{size:IconSizeLg}" Height="{size:IconSizeSm}" /> <!-- non-square override -->

For dynamic non-icon tokens inside a DataTemplate, bind the token key as a string and resolve it with {theme:Lookup {Binding Key}} (or {icons:Lookup {Binding Icon}} when targeting an attached property like theme:Icon.Data).

9AngelSix.Mvvm

The engine is built on AngelSix.Mvvm, and your app can use it too. Derive from ViewModelBase (backed by ObservableObject), expose DI dependencies inline with [Property] or [Observable] on primary constructor parameters, and write single-line cached commands with Command(...) / AsyncCommand(...) for 1-hop Go-to-Definition straight from XAML:

// Quick: type aavm or aavmtheme, then Tab
public sealed partial class MainViewModel(
    [Property] MyTheme theme,
    [Observable(IgnoreNull = true)] string activeSection = "Home") : ViewModelBase
{
    [Observable] public partial string Title { get; set; } = "";

    public IRelayCommand ToggleDarkCommand => Command(() => Theme.IsDark = !Theme.IsDark);
    public IRelayCommand<string?> OpenCommand => Command<string?>(id => Title = id ?? "");
}
  • [Property] on a primary constructor parameter generates public T Name { get; } = param; with zero double-storage.
  • [Observable] works on both partial properties and primary constructor parameters, and supports IgnoreNull = true (ideal when multiple ListBox groups bind to one shared ActiveItem).
  • [NotifyPropertyChanged] gives change notification to a class that already has a base. ThemeBase uses it.
  • Design.DataContext="{DesignContext}" gives the designer the view model named by the view's x:DataType, from the app's services. The App class implements IServiceHost.

10Previews

Each control file carries a {Name}Preview template and a Design.PreviewWith that shows it through LightDarkPreview, side by side in both palettes. theme:Preview.State="Hover" pins a control in a state, so hover, pressed and focused are visible at once. The playground's gallery shows the same templates.

12Attached properties ([Attached<THost>])

Avalonia attached properties normally take ~25 lines of boilerplate per property: AvaloniaProperty.RegisterAttached<…>, Get*, Set*, and a static constructor to wire a change handler. Mark a static readonly AttachedProperty<T> field with [Attached<THost>] on a partial class and the theme engine's source generator writes all of it:

public sealed partial class SwitchKnob
{
    [Attached<ToggleSwitch>]
    public static readonly AttachedProperty<object?> ContentProperty;
}

Supports Default, Inherits = true, and DefaultBindingMode, and automatically wires an On{Name}Changed class handler if you declare one.

Avalonia knowledge

Things Avalonia does that catch you out

Not the engine's rules, but Avalonia's. Each one cost real time to find; each has a one-line fix.

1Style precedence

When more than one thing sets a property, Avalonia picks by priority, and the lowest number wins. The band is decided first: no selector, however specific, beats a lower band.

-1Animationalways winsa running Animation or Transition
0LocalValueset on the element<Border BorderThickness="2" />, or any {Binding}
1StyleTrigger:state or .class selector<Style Selector="Border:pointerover">
2Templatea bare TemplateBindingBorderThickness="{TemplateBinding BorderThickness}"
3Styleplain selector<Style Selector="Border">
4Inheritedfrom a parentFontSize set on an ancestor

That is why a :pointerover style (1) can change a template's value (2), and a plain style (3) is the baseline both start from.

The trap: a wrapped TemplateBinding

Priority comes from the outermost binding assigned to the property, not from anything nested inside it.

✓ Template (2): a state can override it

BorderThickness="{TemplateBinding BorderThickness}"

✕ LocalValue (0): nothing can override it

BorderThickness="{size:Edges {TemplateBinding BorderThickness}}"

Wrapped in any other extension, the TemplateBinding is just a source; the property gets the outer binding, set on the element, so LocalValue. A :pointerover style then does nothing, and even a literal 0 in it is ignored. That's the tell.

The fix: move the value off the element and into a plain style. Then the default is Style (3), the state is StyleTrigger (1), and the state wins.

<!-- default, from a style -->
<Style Selector="^ /template/ RepeatButton">
  <Setter Property="BorderThickness" Value="{size:Edges {TemplateBinding BorderThickness}}" />
</Style>
<!-- the state now wins -->
<Style Selector="^:left /template/ RepeatButton">
  <Setter Property="BorderThickness" Value="0" />
</Style>

Writing your own extension for use in templates? Set Priority = BindingPriority.Template on the binding it returns, so it behaves like a real TemplateBinding when used inline.

2ControlTheme limits

A ControlTheme styles one control and its template. It can't hold a style that reaches other controls through a child or descendant selector; Avalonia throws "ControlTheme style may not directly contain a child or descendent selector".

The fix: put that rule in a plain Styles file in the theme project. The engine loads it with the control files, so there is still nothing to register.

3Transitions that never stop

A transition starts when its property's value changes, and Avalonia compares brushes and transforms by object, not by value. If a binding builds a new brush every time it's read, the transition re-reads it as it starts, sees a "new" value, and starts again, until the stack overflows. Nothing reports it; the app just dies.

The fix: hand back the same object for the same value. The engine does this for every brush and scale transform it produces, so tokens are safe; a converter of your own that feeds a transitioned property needs the same care.

Changelog

What's new in 2.0

  • A theme is one class. DefaultTheme : ThemeBase is both the tokens and the styles: include it as <DefaultTheme /> and it loads every control file in its project itself. No styles class to assemble, no context to build by hand.
  • AngelSix.Mvvm replaces CommunityToolkit. [Observable], [Command] and ResetToDefaults(), source-generated.
  • Ink profiles. The light palette's ink stages come from the theme's InkProfile, so accents read vibrant instead of near-black.
  • The generated Current. Every theme gets a Current accessor: the one instance the app created.
  • {DesignContext}. Design-time data for previews without a view model.
  • Shorthands. {size:Scaled 520}, {size:Edges {…}} and ConcentricCorners defaults.
  • Alignment tokens. StandardAlignment and ButtonAlignment, split into the halves XAML binds.
  • Editor snippets. aaxmlns, aatheme and the rest, written for Rider and VS Code at build time — and aavm, aacmd and friends from AngelSix.Mvvm.
  • Prefix-free <Icon> control. Shipped in AngelSix.Themes.Default: auto-detects bound icon names, Geometry or IImage, defaults to a square via Size, and still allows independent Width/Height overrides.
  • Primary-constructor MVVM & ViewModelBase. ViewModelBase lives in AngelSix.Mvvm; [Property] and [Observable] work directly on primary constructor parameters, and [Observable(IgnoreNull = true)] lets multiple ListBox groups bind cleanly to one ActiveItem.
  • IsLight, DefaultTheme.Accents & [Attached<THost>]. {theme:IsLight} joins {theme:IsDark}; DefaultTheme ships Accents and DefaultAccent; [Attached<THost>] source-generates Avalonia attached properties with Get/Set and change hooks.
  • Shared brushes. One brush instance per color, which fixes a transition stack overflow.
  • Fonts register themselves. AngelSix.ThemeEngine.Fonts embeds Inter (SIL OFL) and registers it on first use: ThemeFonts.Inter, ThemeFonts.System, or the string form. No .WithInterFont().
